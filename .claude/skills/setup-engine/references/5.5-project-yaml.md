# /setup-engine: Populate project.yaml

Read project.yaml first. Edit existing keys in place, never duplicate blocks.
Show the draft and ask "May I write the engine settings to project.yaml?"
unless the task already authorizes it.

```yaml
engine:
  name: web
  version: "Vite 6.4.3 / TypeScript 5.8.3"
  language: TypeScript
  rendering: "Game-owned DOM / Canvas / Pixi / Three"
  physics: "Game-owned logic; no shared physics engine"
  code_root: "apps/rehabtrainerhub/games/<gameId>/"
  test_root: "scripts/check-<gameId>-*.test.mjs"
specialists:
  code: web-game-specialist
  shader: web-game-specialist
  ui: web-game-specialist
  additional: []
testing:
  framework: "node:test"
commands:
  test: "npm run test:game-architecture"
```

The version is today's example, not a default after dependencies change:
read local packages/lockfile every time. New source may live under the game's
src/; preserve existing root entries. Mirror facts to technical-preferences.md.

Do not store literal <gameId> in runnable global commands. Per-game build:
npm --prefix apps/rehabtrainerhub/games/<gameId> run build.
Local browser check:
node scripts/check-r2-game-browser.mjs --game <gameId> --lobby.
Substitute an approved gameId. With no single target keep global build/run/smoke
unset rather than launching Hub as a game fixture.

Never seed modes.review_mode, modes.workflow, docs.density, qa.level,
modes.story_granularity or team.size. Preserve rigor/automation and other keys.
Verify with:
```bash
bash .claude/hooks/yaml-helper.sh resolve_config --keys engine.name,engine.version,engine.language,engine.code_root,engine.test_root,specialists,review_mode,team.size,workflow
```
